<objective>
Implement the repository and API client layers: `OffApiClient` (wraps `openfoodfacts` Dart package for OFF API v3 search), `FoodCatalogRepository` (concrete `IFoodCatalogRepository` combining local DAO + API fallback + cache write + FTS5 index update), and wire everything into DI providers. Also update `main.dart` to run `FirstLaunchExtractor.ensureOffReferenceDb()` before the app mounts.

Purpose: This plan closes the gap between the DAO layer (Plan 02-03) and the state-management layer (Plan 02-05). After caching API results to `UserFoodCacheTable`, the repository also inserts into `user_food_cache_fts` so future local searches find these items without re-hitting the API (per D-API-FALLBACK: "Cached results indexed: FTS5 table in co2diet.sqlite indexes cached items"). After this plan completes, a `FoodSearchNotifier` can call `ref.read(foodCatalogRepositoryProvider)` and get a fully wired repository.

Output: 3 new files + `main.dart` updated. No UI code.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → OFF API | Outbound HTTPS call to world.openfoodfacts.org; response is external, untrusted JSON |
| OFF API response → co2diet.sqlite | API result fields written to local DB + FTS5 index; malformed values must not crash the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Tampering | OFF API response — malformed JSON / unexpected null | mitigate | `_productToFoodItem` uses null-safe `?.` access and fallback values throughout; `result.products?.map(...)` guards null list; malformed product is silently skipped (returns partial FoodItem or excluded from list) |
| T-02-04-02 | Information Disclosure | OFF API — user query sent to external server | accept | OFF API is the designed fallback (LOG-02); query is non-sensitive food name text; user is implicitly consenting when online mode is active; not PII |
| T-02-04-03 | Tampering | Cache insert — malicious product name | mitigate | Parameterized Drift insert (Companion pattern) prevents SQL injection; FTS5 insert uses parameterized `customStatement` with bound variables — product name is never interpolated into SQL string |
| T-02-04-04 | Denial of Service | OFF API timeout causing UI hang | mitigate | `openfoodfacts` client has default timeout; `NetworkException` is caught and surfaced as error state in Plan 02-05 (not blocking the UI thread) |
| T-02-04-05 | Spoofing | User-Agent not set → OFF returns 403 | mitigate | `configureOff()` is called in `main()` before any API call, setting `name: 'CO2Diet'` per Pitfall 6 from RESEARCH.md |
</threat_model>
