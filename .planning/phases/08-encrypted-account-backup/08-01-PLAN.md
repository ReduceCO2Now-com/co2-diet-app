<objective>
Encrypt the backup archive `BackupExportService` already produces, using a user-supplied passphrase (Argon2id -> AES-256-GCM), so the archive is opaque before it ever leaves the device -- the actual privacy property AUTH-09 needs, independent of whether a server ever holds it. Wire this through the existing export/restore pipeline (formatVersion 1 stays untouched; formatVersion 2 is the new encrypted wrapper) and the existing Backup & Restore screen (encrypt toggle with a mandatory unrecoverability warning; restore auto-detects and prompts).

Purpose: 08-RESEARCH.md's key-derivation table rules out a device-held key (fails "restore on another device" by construction) and treats a Keycloak-derived key as a weaker, non-default trade -- a user-supplied passphrase is the only option satisfying both "opaque to the server" and "portable to any device". This plan is independent of the backend and is fully verifiable today (round trip, tamper, wrong-key, all runnable in plain `flutter test`), which is why 08-CONTEXT.md locks it to land first, regardless of what happens to 08-02/08-03.

Output: `pointycastle` installed and human-approved; `BackupArchiveCipher` (pure crypto primitive); `BackupExportService` producing/consuming formatVersion 2 encrypted archives alongside unchanged formatVersion 1 plaintext ones; a passphrase-creation and passphrase-entry UI wired into the existing Backup & Restore screen; a device-measured encrypt/decrypt benchmark; the `Info.plist` export-compliance key set deliberately.
</objective>
