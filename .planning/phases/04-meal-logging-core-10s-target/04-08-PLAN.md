<objective>
Replace the `/custom-food-stub` placeholder with the real custom-food/override form (LOG-10, LOG-11) and add the My Foods list screen reachable from Settings. This closes the "Add as custom food" no-match/no-results dead ends Phase 2/3 explicitly deferred.

Purpose: This plan delivers the full custom-food and personal-override authoring surface. It does not yet wire the "Edit this food" button inside `FoodDetailBottomSheet` (that's Plan 04-09, which navigates here) or the search no-results link (Plan 04-10) — this plan defines and owns the route contract those callers use.

**Route contract** (both existing and new callers depend on this): `GET /custom-food-stub` accepts optional query params:
- `barcode` — pre-fills the barcode field (existing contract from `BarcodeScanNoMatchScreen`, unchanged)
- `name` — pre-fills the name field (NEW — used by the search no-results "Add as custom food" link, Plan 04-10)
- `overrideOf` + `overrideOfSource` — when both present, the form loads the original food's current values (via `IFoodCatalogRepository.lookupByBarcode` for `off_ref`/`user_food_cache`, or a direct catalog lookup) as starting values and saves as an override (NEW — used by `FoodDetailBottomSheet`'s "Edit this food" action, Plan 04-09)
- `userFoodId` — when present, loads an existing `UserFood` row directly for editing (NEW — used by My Foods list row taps, this plan)

Output: Custom food form screen, dynamic serving-size editor widget, My Foods list screen, updated router and Settings navigation.
</objective>
