<objective>
Extend the existing Phase 2/3 food search and barcode lookup chain (`FoodCatalogDao`, `FoodCatalogRepository`) so a personal override in `UserFoodTable` takes precedence over the catalog/cache row it overrides — satisfying LOG-11's "search shows only the override" requirement without touching the original row. Also give `FoodItem` a single authoritative, stable merge-key resolution rule (CONTEXT.md Merge Semantics: "the food's internal reference/ID — barcode when present, otherwise catalog/custom-food ID — never a product-name string match"), and define the `MealEntry`/`Favorite` → `FoodItem` reverse-mapping extensions that later UI plans need for pre-filling the logging sheet from an existing entry.

Purpose: This is a cross-cutting change to existing Phase 2/3 production code, isolated into its own plan (per the split-signal guidance for changes with real regression risk to already-shipped, tested code) so it can be verified independently against the full existing `food_catalog_dao_test.dart`/`food_catalog_repository_test.dart` suites without being buried inside a larger DAO-creation plan. It is also the earliest plan in the dependency graph where both `FoodItem.source` (this plan) and the `MealEntry`/`Favorite` entities (Plan 04-03, already available transitively via Plan 04-04) coexist — making it the correct single owner of `toFoodItem()`, so downstream Plans 04-09 (which builds `FoodItem.resolvedFoodRef`-keyed `MealEntry` drafts), 04-10, and 04-11 (both of which need `toFoodItem()` for edit-prefill, and both run in the same wave 7 with no dependency between each other) can all consume one already-built, already-tested implementation instead of each independently defining or racing to define it.

Output: `FoodItem` gains `source`, `sourceRowId`, and a `resolvedFoodRef` getter; `FoodCatalogDao` and `FoodCatalogRepository` check `UserFoodTable` for an override before returning catalog/cache results; a new `meal_entry_food_item_mapping.dart` file provides `MealEntry.toFoodItem()`/`Favorite.toFoodItem()`.
</objective>
