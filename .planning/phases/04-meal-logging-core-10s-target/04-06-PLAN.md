<objective>
Extend the existing Phase 2/3 food search and barcode lookup chain (`FoodCatalogDao`, `FoodCatalogRepository`) so a personal override in `UserFoodTable` takes precedence over the catalog/cache row it overrides — satisfying LOG-11's "search shows only the override" requirement without touching the original row.

Purpose: This is a cross-cutting change to existing Phase 2/3 production code, isolated into its own plan (per the split-signal guidance for changes with real regression risk to already-shipped, tested code) so it can be verified independently against the full existing `food_catalog_dao_test.dart`/`food_catalog_repository_test.dart` suites without being buried inside a larger DAO-creation plan.

Output: `FoodItem` gains a `source` field; `FoodCatalogDao` and `FoodCatalogRepository` check `UserFoodTable` for an override before returning catalog/cache results.
</objective>
