## Pre-flight

The app must be in a genuinely un-onboarded state. `hasCompletedOnboarding` is
a `SharedPreferences` bool — reinstalling without clearing storage will **not**
reset it on Android.

**Android**
```bash
adb shell pm clear com.reduceco2now.co2diet
flutter run -d <device-id>
```

**iOS simulator**
```bash
xcrun simctl uninstall booted com.reduceco2now.co2diet
flutter run -d <device-id>
```

**iOS device** — delete the app from the home screen, then reinstall.

- [ ] App storage cleared, not just reinstalled
- [ ] `flutter run` targets one explicit device (`-d`). With several devices
      attached the build can land on the wrong one — this cost a session
      during Phase 9
- [ ] Screen reader **off** for Part A, on for Part B

## Part C — Persistence

| # | Step | Expect | ✅ / ❌ |
|---|---|---|---|
| C1 | Force-quit from the app switcher, relaunch | Opens **directly to Dashboard**, not Splash | |
| C2 | Background 30 s, return | Dashboard, no re-onboarding | |
| C3 | *(Android)* `adb shell am kill com.reduceco2now.co2diet`, relaunch | Dashboard | |

> C3 uses `am kill`, not force-stop. Force-stop puts the app in the OS "stopped"
> state and suppresses background execution — a harsher, unrepresentative
> condition. `am kill` simulates a genuine low-memory eviction. Same distinction
> established during Phase 9 device testing.

## Failure triage

| Symptom | Likely cause | Look at |
|---|---|---|
| Loops back to Splash after Profile Setup | `completeOnboarding()` not firing, or awaited state dropped | `profile_screen.dart:42-43` |
| Nav bar visible on Carousel or Profile Setup | `AppShell` gate not reading `onboardingGateProvider` | `app_router.dart` — `AppShell.build` |
| Completion lost on restart | Provider `autoDispose` disposing mid-`await` (`UnmountedRefException`) — the exact Phase 6 bug | `onboarding_gate_provider.dart` — confirm `keepAlive: true` |
| Carousel appears *after* Profile Setup | Reorder not in the running build | Rebuild; confirm `06.1-01` commits present |
| Profile Setup appears straight after Legal Consent | The orphaned-Carousel bug is back | `legal_consent_screen.dart` — `_onAccept` must go to `/connectivity-choice` |
| Last-slide button still says "Go to Dashboard" | Stale build, or only one exit path updated | `onboarding_carousel_screen.dart:165` |
| "Skip intro" lands on Dashboard | Completion call not removed from that path | `onboarding_carousel_screen.dart` |
| Screen reader reaches nav items early | Bar hidden by opacity/visibility rather than omitted | `AppShell` — must return `null`, not a styled bar |

Two of these — the `autoDispose` disposal and the nav-bar bypass — are
**regressions of bugs already fixed in `06-10`**, and this reorder touches both
call sites. They are the highest-probability failures here.
