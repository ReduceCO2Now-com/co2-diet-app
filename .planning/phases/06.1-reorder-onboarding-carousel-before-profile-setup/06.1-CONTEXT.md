# Phase 06.1: Reorder onboarding: Carousel before Profile Setup - Context

**Gathered:** 2026-09-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Reorder the currently-shipped, locked onboarding flow from `Splash → Welcome → Legal Consent → Profile Setup → Carousel → Dashboard` to `Splash → Welcome → Legal Consent → Carousel → Profile Setup → Dashboard`. This is a deliberate UX reconsideration (explain the app's purpose before asking for personal data), not a bug fix — the pre-reorder flow was confirmed working exactly as spec'd during Phase 6's 06-10 real-device verification. Nothing about *what* each screen does changes, only *when* it runs and which screen owns the "onboarding complete" trigger.

**Out of scope:** any new screens, new onboarding steps, Mode Choice, or content/feature changes to Profile Setup or the Carousel beyond what the reorder itself forces (button destinations/labels, completion-trigger call site).

</domain>

<decisions>
## Implementation Decisions

### Onboarding-Completion Trigger
- `OnboardingGateNotifier.completeOnboarding()`'s call site **moves from the Carousel to Profile Setup** — Profile Setup is now the last onboarding step, so it owns flipping `hasCompletedOnboarding`.
- The Carousel becomes a **pure pass-through**: both its exit buttons navigate to `/profile` and do **not** call `completeOnboarding()`.
- This preserves the 06-10 bug fix intact: the bottom nav (`AppShell`, keyed off `onboardingGateProvider`) stays hidden through **both** the Carousel and Profile Setup, so there's still no shortcut to bypass Profile Setup via the nav bar. Flipping the trigger at Carousel-exit instead (i.e., leaving it where it is today) was explicitly rejected — it would reintroduce that exact bug.

### Route Guard
- **No changes to the redirect guard's `onboardingOnlyRoutes` allowlist** (`lib/core/router/app_router.dart`). `/profile` is already deliberately excluded from that list (shared pre-/post-onboarding via `AppShell`, per existing code comment) — only the `completeOnboarding()` call site is moving, not any route's membership in the allowlist.
- Code comments in `app_router.dart` and `AppShell` that describe the old flow order ("Profile Setup → Carousel") need updating to reflect the new order — mechanical, not a routing-logic change.

### Screen CTAs & Copy
- **Carousel top-right "Skip intro" button:** label unchanged (it describes skipping the slides, not a destination) — destination changes to `/profile`, no `completeOnboarding()` call.
- **Carousel last-slide button:** relabel from `"Go to Dashboard"` to **`"Set Up Profile"`** — destination `/profile`, no `completeOnboarding()` call. (Considered keeping "Go to Dashboard" unchanged for minimal copy churn; rejected as inaccurate now that it doesn't go to the Dashboard.)
- **Profile Setup's forward button:** relabel from `"Continue"` to **`"Go to Dashboard"`** — now the terminal onboarding action; calls `completeOnboarding()` then `context.go('/dashboard')`. Mirrors the exact label the old last step (Carousel) used, keeping the "last step says Go to Dashboard" convention intact.

### Skip Affordance
- **No new "Skip for now" link added to Profile Setup.** Its fields are already optional and auto-save (06-CONTEXT.md's "no blocking validation" principle) — tapping the forward button with zero fields filled already functions as the skip path. A separate skip link would be redundant UI for the same action.

### Carousel Content
- **Slide text ships unchanged.** Verified directly against the live source (`lib/features/onboarding/screens/onboarding_carousel_screen.dart` lines 21–46) — all three slides' literal heading + body text contain zero recap-style language (no "as you just set up," "based on your goal," or similar) and read equally well as a lead-in before Profile Setup as they did as a recap after it.
- The **code doc-comment** above the `OnboardingCarouselScreen` class (currently: *"shown after Profile Setup, before the Dashboard"*) does need updating to reflect the new order — this is developer-facing documentation, not user-visible copy, and is Claude's discretion to word.

### Verification Scope
- **Per-screen accessibility properties are unaffected by the reorder** — contrast, dark mode, tap-target sizes, and VoiceOver/TalkBack labels are intrinsic to each screen and don't change with sequence. No need to redo Phase 6's full 06-10 accessibility audit.
- **Flow-level behavior does need a lightweight re-verification pass**, since that's exactly what this phase touches: the redirect guard / bottom-nav-hide behavior across the new sequence, and a screen-reader pass confirming Carousel → Profile Setup → Dashboard reads sensibly in the new order. Scope and format (formal UAT doc vs. a lighter manual check) is Claude's discretion during planning.

### Claude's Discretion
- Exact wording of updated code comments (`OnboardingCarouselScreen` doc comment, `AppShell` comment, router comments describing flow order).
- Existing test file updates needed for the new route/trigger sequence (which files, exact assertions).
- Whether the flow-level re-verification is a formal UAT.md-style document or a lighter inline manual-check note.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `OnboardingGateNotifier.completeOnboarding()` (`lib/features/onboarding/providers/onboarding_gate_provider.dart`) — logic itself is unchanged; only its call site moves from `OnboardingCarouselScreen._finishOnboarding()` to `ProfileScreen`'s forward-button handler.
- `AppShell`'s bottom-nav-hide logic (`lib/core/router/app_router.dart` ~lines 84–132) — already correctly keyed off `onboardingGateProvider`; no logic change needed, only its explanatory comment (which currently narrates the pre-reorder flow) needs updating.
- Router redirect guard's `onboardingOnlyRoutes` / `allowedPreOnboarding` lists (`app_router.dart` ~lines 152–169) — `/profile` is already outside `onboardingOnlyRoutes` by design; no membership changes needed.

### Established Patterns
- `go_router` named routes with `context.go(...)` — same navigation pattern used throughout; no new pattern introduced by this reorder.
- Riverpod `@Riverpod(keepAlive: true)` for app-lifetime gate state (`OnboardingGateNotifier`, `sharedPreferencesProvider`) — unchanged, same instance, only the caller changes.

### Integration Points
- `lib/features/onboarding/screens/onboarding_carousel_screen.dart` — `_finishOnboarding()` (or its two call sites) changes to a plain `context.go('/profile')` with no `completeOnboarding()` call; last-slide button label changes to "Set Up Profile".
- `lib/features/profile/screens/profile_screen.dart` (~lines 129–141) — the onboarding-only forward button's `onPressed` changes from `() => context.go('/onboarding-carousel')` to a handler that awaits `completeOnboarding()` then `context.go('/dashboard')`; label changes from "Continue" to "Go to Dashboard".
- `lib/core/router/app_router.dart` — no routing-logic changes; comment updates only (flow-order narration in `AppShell`'s doc comment and the redirect guard's inline comments).

</code_context>
