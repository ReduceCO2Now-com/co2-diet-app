<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User keyboard input → ProfileForm | Age, height, weight values arrive as raw strings from TextFormField |
| ProfileForm → ProfileNotifier | Parsed Dart values (int?, double?, String?) cross into the notifier's updateField |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Extreme numeric input in profile fields (e.g. age = 999, weight = 0.001) | mitigate | ProfileForm parses via tryParse — invalid strings produce null (field is cleared, not crashed); TargetCalculator returns null CalcTargets for nonsensical combinations; Phase 6 ED safety net (NFR-07) adds explicit guardrails |
| T-05-02 | Information Disclosure | Height/weight rendered in UI (sensitive biometrics) | accept | Displayed only to the authenticated device user; no network call; no analytics SDK per CI blocklist |
| T-05-03 | Tampering | Override dialog accepting arbitrary kcal values | mitigate | TextFormField keyboardType: number; parsed via double.tryParse — null on non-numeric; TargetCalculator output clamp (500–10000 kcal) documented in T-03-01; Phase 6 adds clinical safety net |
| T-05-04 | Spoofing | go_router deep-link to a sensitive route | accept | No sensitive data routes in Phase 1; deep-link handling is a Phase 7 concern (auth gates); accepted |
| T-05-SC | Tampering | pub.dev package installs | accept | No new packages; go_router and riverpod_annotation already in pubspec from Plan 01-01 |
</threat_model>
