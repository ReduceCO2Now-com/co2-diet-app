      # Any transitive dependency matching a prefix causes CI to fail.
      # To add/remove entries: open a PR; the change is auditable via git history.
      blocked_prefixes:
        - firebase_

    Note: the CONTEXT.md lists 8 prefixes as the minimum; this plan adds 6 more (appsflyer_, adjust_, braze_, clevertap, leanplum, moengage) that are equally common analytics/ad SDKs. Adding them now costs nothing.

    scripts/check_privacy_deps.dart — standalone Dart script (no Flutter dependency, no pub package dependencies beyond dart:io, dart:convert):

    The script:
      1. Reads two CLI arguments: pubspec.lock path and blocklist yaml path (positional args: args[0] and args[1]).
      2. Parses pubspec.lock — this is a YAML file. Since we cannot import a yaml package here (the script may run before pub get), parse the packages section manually:
         - Read the file as a string.
         - Extract package names using a RegExp that matches lines like `  package_name:` under the `packages:` key.
         - Specifically: find the line `packages:` then match all lines of the form `^\s{2}([a-z][a-z0-9_]*):$` (two-space indent followed by package name and colon). This matches exactly the pubspec.lock format.
      3. Parses .privacy-blocklist.yaml manually (same approach — no yaml package):
         - Find lines after `blocked_prefixes:` that start with `    - ` (4-space indent and dash).
         - Extract the prefix string after the dash and trim whitespace.
      4. For each package name found in pubspec.lock, check if it starts with any blocked prefix.
      5. Collect all violations into a list.
      6. If violations is empty: print 'OK: N packages checked, 0 violations' and exit(0).
      7. If violations is non-empty: print each violation as 'BLOCKED: package_name (matches prefix "prefix_")' and exit(1).

    The script must NOT import any pub package. Only dart:io for file reading and process exit, and dart:core.

    After writing the script, verify it works locally:
      dart run scripts/check_privacy_deps.dart pubspec.lock .privacy-blocklist.yaml
    Expected: exits 0 with "OK: N packages checked, 0 violations" because the Phase 1 pubspec contains no blocked packages.

    Also do a quick manual test with a fake entry: temporarily add `firebase_core: 0.0.0` to a copy of pubspec.lock and verify the script exits 1. (Do not commit the fake entry — just verify behavior.)

    name: CI

    on:
      push:
        branches: [main]
      pull_request:
        branches: [main]

    jobs:

      analyze-test-android:
        name: Analyze, Test & Build (Android)
        runs-on: ubuntu-latest

        steps:
          - name: Checkout
            uses: actions/checkout@v4

          - name: Set up Flutter 3.44.6
            uses: subosito/flutter-action@v2
            with:
              flutter-version: '3.44.6'
              channel: 'stable'
              cache: true
              cache-key: flutter-${{ hashFiles('pubspec.lock') }}

          - name: Restore pub cache
            uses: actions/cache@v4
            with:
              path: ~/.pub-cache
              key: pub-cache-${{ runner.os }}-${{ hashFiles('pubspec.lock') }}
              restore-keys: |
                pub-cache-${{ runner.os }}-

          - name: Get dependencies
            run: flutter pub get

          - name: SDK blocklist audit (PRIV-07)
            run: dart run scripts/check_privacy_deps.dart pubspec.lock .privacy-blocklist.yaml

          - name: Analyze
            run: flutter analyze --no-fatal-warnings

          - name: Run tests
            run: dart test

          - name: Restore build cache
            uses: actions/cache@v4
            with:
              path: |
                build/
                .dart_tool/
              key: build-android-${{ runner.os }}-${{ hashFiles('pubspec.lock', 'lib/**') }}
              restore-keys: |
                build-android-${{ runner.os }}-

          - name: Build APK (debug)
            run: flutter build apk --debug

      build-ios:
        name: Build iOS (no codesign)
        runs-on: macos-latest

        steps:
          - name: Checkout
            uses: actions/checkout@v4

          - name: Set up Flutter 3.44.6
            uses: subosito/flutter-action@v2
            with:
              flutter-version: '3.44.6'
              channel: 'stable'
              cache: true
              cache-key: flutter-${{ hashFiles('pubspec.lock') }}

          - name: Restore pub cache
            uses: actions/cache@v4
            with:
              path: ~/.pub-cache
              key: pub-cache-${{ runner.os }}-${{ hashFiles('pubspec.lock') }}
              restore-keys: |
                pub-cache-${{ runner.os }}-

          - name: Get dependencies
            run: flutter pub get

          - name: Remove extended attributes from Flutter (Xcode 26 workaround)
            run: xattr -cr "$HOME/flutter" 2>/dev/null || true

          - name: Build iOS (no codesign)
            run: flutter build ios --no-codesign

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pubspec.lock → CI blocklist script | The script reads the lock file produced by pub get and checks it against the local blocklist config |
| GitHub Actions runner → pub.dev | pub get fetches packages; blocklist audit runs immediately after to verify nothing blocked was pulled in transitively |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure | Transitive analytics SDK slipping in via a legitimate package | mitigate | Blocklist runs on pubspec.lock after every pub get on every PR; any match → CI fails and merge is blocked |
| T-06-02 | Tampering | Modifying .privacy-blocklist.yaml to remove a prefix | mitigate | Change requires a PR; git history is auditable; branch protection requires CI green (which includes the same blocklist) |
| T-06-03 | Tampering | check_privacy_deps.dart parsing failure leaving gaps | mitigate | Script parses pubspec.lock format that is stable (pub team controls it); RegExp targets the exact two-space-indented package name pattern; test in Plan 01-07 (blocklist_test.dart) verifies both exit-0 and exit-1 paths |
| T-06-04 | Tampering | CI workflow file modified to skip blocklist step | mitigate | Branch protection (manual setup in GitHub UI) requires the CI checks to pass; removing the blocklist step would cause the check-name to disappear, breaking the branch protection rule |
| T-06-SC | Tampering | pub.dev package installs in CI | mitigate | All packages already in pubspec from Plan 01-01 with Approved disposition in RESEARCH.md Package Legitimacy Audit; blocklist CI itself catches violations |
</threat_model>
