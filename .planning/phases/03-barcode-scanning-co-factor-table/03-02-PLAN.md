LIMIT 1`, selecting the same columns plus `cf.co2e_median AS co2e_100g, 'medium' AS confidence_band`. Note: the ingest pipeline (Task 2) adds a `primary_category_tag TEXT` column to `off_ref.products` — use this column rather than the `json_each` approach from RESEARCH.md to avoid Pitfall 5. If rows non-empty, return the FoodItem.

    Return null if both steps find nothing. Also add a `Future<FoodItem?> lookupByBarcodeFromApi(String barcode, FoodItem apiResult) async` stub that accepts an already-fetched API FoodItem and applies the CO₂ category join (Step 2 logic but starting from the API result's category tag) — this stub will be called by the BarcodeScanNotifier in Plan 03 for Step 3 of the lookup chain.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Tampering | FoodCatalogDao.lookupByBarcodeWithCo2 | mitigate | Barcode passed as `Variable.withString(barcode)` in customSelect — parameterized query prevents SQL injection. Max-length guard (>13 chars → return null) prevents oversized inputs. |

</threat_model>
