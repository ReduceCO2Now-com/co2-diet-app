<objective>
Build the Backup & Restore screen per the Full Reference doc's existing spec (CONTEXT.md): Current Storage Status, Create Backup, Automatic Backups, Restore Data, Export Data, Privacy & Ownership statement, and a typed-confirmation Danger Zone. Not yet linked from `SettingsScreen` or wired into `app_router.dart` — Plan 05-18 adds both.

Purpose: This is the UI layer over `BackupExportService` (05-09) — all zip/CSV/Excel/JSON/zip-slip logic already exists; this plan is presentation + `share_plus` invocation + the Danger Zone's typed-confirmation gate (PRIV-09).

**Locked decision (05-CONTEXT.md Planning Addendum, resolving a plan-checker scope_reduction finding):** the original draft of this plan only let the user browse backups still sitting in the app's own documents directory, which silently fails for the realistic restore scenario (after a reinstall, or restoring on a new device, where the app's documents directory is empty). This revision adds `file_selector` — the official `dart-lang`/`flutter` team's federated file-picker plugin (`github.com/flutter/packages`), chosen over the more commonly-recalled `file_picker` community package specifically because it's the officially-maintained, minimal, no-analytics option, consistent with this project's existing preference for well-established, auditable dependencies — gated behind the same package-legitimacy checkpoint pattern used for every other new dependency this phase. Restore Data now opens a real OS document picker so the user can import a backup zip from anywhere (Files app, cloud-synced folder, AirDrop'd file, etc.), not only from this app's own sandboxed storage.

Also resolves RESEARCH.md Open Question 1 (encryption): **no encryption in v1**, explicitly disclosed in the Privacy & Ownership statement below, with `manifest.json`'s `formatVersion` field (05-09) keeping a future encrypted format addable without breaking old backups.

Output: `BackupNotifier`, `BackupRestoreScreen`, `DangerZoneSection`, with `file_selector` installed for genuine external-file restore.
</objective>
