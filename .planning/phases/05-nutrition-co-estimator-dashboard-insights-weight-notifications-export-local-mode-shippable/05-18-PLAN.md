<objective>
Wire every standalone Wave 5/6 screen into the app: add the four new go_router routes, assemble the Dashboard from Plan 05-11's widgets plus quick-log buttons (DASH-02) and the metric-tap-to-Data-Analysis behavior (DASH-08), add General Settings entry points for CO2 Calculation Settings / Weight Tracking / Backup & Restore, embed Plan 05-14's meal reminder settings section into General Settings, extend `FoodSearchScreen` to accept a pre-selected meal slot (shared by both the Dashboard's quick-log buttons and Plan 05-08's notification-tap payload contract), and add the root-level app-lifecycle observer that re-arms biweekly/monthly weigh-in reminders on every foreground event.

Purpose: Every prior Wave 5/6 plan deliberately built its screen/widget standalone to maximize parallelism with zero `app_router.dart`/`settings_screen.dart` conflicts. This plan is the single integration point that makes all of it reachable — the last piece before Phase 5's Local Mode is genuinely shippable.

**Locked decision (05-CONTEXT.md Planning Addendum):** `flutter_local_notifications` has no native biweekly/monthly recurrence, and Plan 05-08's `NotificationService.scheduleWeighInReminder` is a pure, stateless "schedule the next occurrence now" call — something needs app-lifecycle visibility to re-invoke it periodically. This plan is that something: `Co2DietApp` (`lib/app.dart`) becomes a `ConsumerStatefulWidget` with a `WidgetsBindingObserver`, and on every `AppLifecycleState.resumed` it reads the current `WeightSettings` (via `weightProvider`, built in Plan 05-07) and re-arms the weigh-in reminder when one is enabled — in addition to (not instead of) Plan 05-13's existing screen-open call.

Output: Four new routes, a fully composed Dashboard, three new Settings entry points plus the embedded meal-reminder section, slot-aware `FoodSearchScreen`, and the app-lifecycle weigh-in re-arm observer.
</objective>
