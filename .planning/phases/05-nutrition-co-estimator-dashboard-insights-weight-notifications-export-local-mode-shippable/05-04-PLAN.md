<objective>
Extend `FoodItem` and `MealEntry` with the three nutrient fields NUTR-01 requires (sugar, fiber, and salt-as-sodium — see 05-03's naming decision), and wire the write path so a logged `MealEntry` actually carries these values through from whichever source food produced it.

Purpose: 05-03 added the `MealEntryTable` columns; this plan makes them reachable. `FoodItem` (the in-memory representation of an off_ref/user_food_cache/user_foods product before it's logged) currently has no sugar/fiber/salt fields at all, so even personal overrides and custom foods — which DO carry this data in `UserFoodTable` — silently lose it once mapped through `FoodCatalogDao._foodItemFromUserFoodRow`. This plan closes that gap end-to-end: `UserFoodRow` -> `FoodItem` -> `MealEntry` draft -> `MealEntryRow`.

Output: `FoodItem` and `MealEntry` gain three new nullable fields each (with `copyWith`/`fromRow`/`==`/`toString` updated), `ScaledMacros` gains scaled sugar/fiber/salt, and `MealEntryRepository.logOrMerge` persists the new fields.
</objective>
