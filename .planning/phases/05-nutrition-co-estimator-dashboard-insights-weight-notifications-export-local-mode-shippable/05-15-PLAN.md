<objective>
Build the Data Analysis screen: today's breakdown by meal as a real stacked bar chart, an explicit weekly-total figure, ranked Largest Contributors, goal comparison (progress bar + dynamic message), an independently-toggleable metric x range trend section, a richer aggregate Estimate Transparency panel, and a per-meal-entry expandable Detailed Food Analysis panel. Includes the Weight entry in the screen's own metric list (WT-05). Not yet wired into `app_router.dart` or reachable from the Dashboard — Plan 05-18 adds the route and Dashboard-tap wiring; Plan 05-17 (next wave) adds Improvement Opportunities and the Insights Timeline into this same screen file.

Purpose: INS-01/INS-02 are this phase's richest single screen. `DataAnalysisScreen` accepts an `initialMetric` constructor parameter (`co2`/`calories`/`protein`/`weight`) so it's fully testable standalone and ready for Plan 05-18 to wire `state.uri.queryParameters['metric']` through once the route exists.

**Revision note (plan-checker findings, resolved):** REQUIREMENTS.md literally specifies "today's breakdown by meal (stacked bar)" — the original draft of this plan substituted a plain grouped list, which under-delivered the requirement. `fl_chart` is already a phase dependency (installed by Plan 05-08 for the Dashboard/Weight trend work), so this plan uses `BarChart` + `BarChartRodStackItem` directly, no new package. Separately, ROADMAP.md's CO2-02 success criterion requires "daily / weekly totals," and the original draft only ever surfaced day-by-day 7d/30d trend charts with no single "this week's total" figure — this plan adds `WeeklyTotalSummary`, computed via the same generic `DailyTotalsCalculator.compute()` already used for today's totals, just called over the trailing 7 days' pooled entries instead.

**Second revision note (plan-checker dependency_correctness finding, resolved):** the prior draft had this plan import/extend `DashboardMetric` from `lib/features/dashboard/widgets/trend_sparkline.dart` — a file owned by Plan 05-11, a same-wave (Wave 5) sibling with no `depends_on` edge from this plan. Same-wave plans with no dependency edge run in parallel with no ordering guarantee, so this plan cannot safely assume 05-11's file exists yet. This plan now defines its own, fully self-contained `AnalysisMetric` enum (`lib/features/data_analysis/widgets/analysis_metric.dart`) instead of importing or extending anything from `lib/features/dashboard/`.

Output: `DataAnalysisScreen` plus seven supporting widgets, all reading from `DailyTotalsCalculator` (05-10) and `Co2Settings`/confidence-band data already carried on every `MealEntry`.
</objective>
