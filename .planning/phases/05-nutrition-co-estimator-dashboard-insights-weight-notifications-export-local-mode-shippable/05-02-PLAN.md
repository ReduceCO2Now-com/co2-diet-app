<objective>
Fix the Phase 4 CO2 cache-path gap folded into this phase per CONTEXT.md/RESEARCH.md Pitfall 4: `FoodCatalogRepository.lookupByBarcode`/`.searchAndCache` hardcode `categoriesTags: const Value(null)` when caching API-fallback results, and `FoodCatalogDao.searchLocalFoods`'s `user_food_cache_fts` query branch hardcodes `NULL AS co2e_100g, NULL AS confidence_band` with no join at all. Together these mean a product fetched once via the API never shows a CO2 estimate on later offline searches, even when its category has a `co2_factors` match.

Purpose: This phase is already deep in CO2 calculation code (CO2-02/CO2-03/CO2-05/CO2-06); fixing this now is far cheaper than reopening the food-catalog cache path cold in a later phase. Fixes CO2-02's "deterministic, on-device" promise for the cached-result code path and closes an NFR-05 honesty gap (a product silently losing its CO2 estimate after being cached is a worse experience than showing no estimate consistently).

Output: Cache-write path stores a single most-specific category tag; cache-read path joins `off_ref.co2_factors` on that tag, mirroring the existing `off_ref.products` branch's join shape. The Wave 0 stub test is de-skipped into real assertions.
</objective>
