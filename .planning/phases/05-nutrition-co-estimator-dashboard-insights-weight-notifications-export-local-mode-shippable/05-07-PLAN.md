<objective>
Build the Weight Tracking domain layer: `WeightEntry`/`WeightSettings` entities, `IWeightRepository` + Drift-backed implementation, DI providers, and `WeightNotifier` — one cohesive vertical covering logging (WT-01), history retrieval (WT-02), goal (WT-03), and reminder config (WT-04), mirroring `IMealEntryRepository`'s established precedent of one repository/notifier owning multiple closely-related concerns.

Purpose: This is the data layer the Weight Tracking screen (Plan 05-13) and Data Analysis's Weight metric entry (Plan 05-15) both consume. CONTEXT.md's explicit rejection of any derived "on pace"/projection value is enforced at the entity level here — `WeightSettings` has no such field, so a later screen literally cannot render one by accident.

Output: `WeightEntry`, `WeightSettings`, `IWeightRepository`, `WeightRepository`, `weightRepositoryProvider`, and `WeightNotifier` (generated provider: `weightProvider`).
</objective>
