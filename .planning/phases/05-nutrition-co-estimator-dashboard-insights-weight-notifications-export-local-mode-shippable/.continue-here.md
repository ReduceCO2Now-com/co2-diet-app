**Test 5 (meal reminder) found a real, severe bug affecting BOTH meal AND weigh-in reminders -- FIXED, commit `025bc55`, not yet real-device confirmed:**
- User ruled out device/permission causes first (reminder time correct, notification permission granted, battery optimization not restricting the app) before asking for a code-level investigation -- exactly the rigor this session has consistently required.
- Root cause: `NotificationService.initialize()` never actually called `tz_data.initializeTimeZones()`/`tz.setLocalLocation(...)`, despite its own doc comment claiming it does. The `timezone` package's `tz.local` is a package-global `late Location _local` field with NO default -- the first read of it (inside `_nextInstanceOfTime`, used by both `scheduleMealReminder` and `scheduleWeighInReminder`) threw `LateInitializationError`. That's not a `PlatformException`, so neither method's own `try/catch` caught it -- it propagated uncaught, silently, with zero user-visible error, out of `NotificationPrefsNotifier.setSlotEnabled` (meal) and the weigh-in reminder's scheduling call. `flutter_timezone` was already a human-approved dependency installed in Plan 05-08 for exactly this purpose, but never wired up anywhere.
- Reproduced first: a widget test deliberately isolated from the existing `notification_service_test.dart` (whose `setUpAll` pre-seeds `tz.setLocalLocation`, masking this exact gap for every test in that file) -- `test/domain/services/notification_service_timezone_test.dart` confirmed `scheduleMealReminder` throws `LateInitializationError` against current code.
- Fix: `initialize()` now calls `tz_data.initializeTimeZones()` then resolves+sets the device's real IANA timezone via `FlutterTimezone.getLocalTimezone()`, with a graceful UTC fallback if the platform channel is unavailable. A second test confirms the real device-timezone path works too, not just the fallback.
- Full suite (376 tests) green, `flutter analyze` clean.
- **This single fix covers both Test 5 (meal reminder) and Test 6 (weigh-in reminder) -- ask the user to retest both together next**, since they were both reported broken by the identical root cause.
