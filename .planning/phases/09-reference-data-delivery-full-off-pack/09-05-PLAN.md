    build() returns the current ReferencePackStatus by composing referencePackRepositoryProvider's watchStatus() stream with a seed default -- expose Stream&lt;ReferencePackStatus&gt; as an AsyncNotifier-style state (evaluate whether AsyncNotifier&lt;ReferencePackStatus&gt; watching the repository's stream, or a plain Notifier reading a one-shot status plus separately watching the stream, fits this project's existing precedent better; BackupNotifier's precedent -- AsyncNotifier whose build() awaits a single Future -- does not fit a continuously-updating download-progress stream as cleanly as watching a StreamProvider would, so prefer wiring watchStatus() through ref.watch(referencePackStatusStreamProvider) as a separate @riverpod StreamProvider that this notifier composes, keeping ReferencePackNotifier itself a thin AsyncNotifier that also exposes the mutation methods below).

    Mutation methods, each delegating to referencePackRepositoryProvider and never touching background_downloader/connectivity_plus/storage_space directly: Future&lt;ReferencePackManifest&gt; checkForUpdate() (fetches the manifest, does not start any download); Future&lt;bool&gt; hasEnoughDiskSpace(ReferencePackManifest manifest); Future&lt;bool&gt; isOnWifi() (wraps connectivity_plus's Connectivity().checkConnectivity(); the structural pattern of calling Connectivity().checkConnectivity() and inspecting the returned List&lt;ConnectivityResult&gt; is reused from food_search_notifier.dart/auth_screen.dart's existing connectivity checks, but the specific check performed here is new, not mirrored -- those two existing call sites both check list.contains(ConnectivityResult.none) for an offline/online determination; neither checks for ConnectivityResult.wifi. This method's positive Wi-Fi-vs-cellular distinction (list.contains(ConnectivityResult.wifi)) is new logic this plan introduces. This is the one place in the Reference Data feature that talks to connectivity_plus directly, since it is a UI-facing "should I prompt the user" decision, not a data-layer concern); Future&lt;void&gt; startFullDownload({required bool allowCellular}); Future&lt;void&gt; cancelDownload(); Future&lt;void&gt; resumeDownload() (trivial delegation to referencePackRepositoryProvider's IReferencePackRepository.resumeDownload(), already declared in Plan 09-02's interface -- called by ReferenceDataScreen's Task 3 "Resume" button when status is ReferencePackFailed(canResume: true), per CONTEXT.md's manual-Resume-only convention); Future&lt;void&gt; revertToSeed() (only callable when the repository's isDownloadInProgress() is false -- surfaces a StateError otherwise, which the calling screen is expected to have already prevented via a disabled button, not something a user should ever actually trigger).
