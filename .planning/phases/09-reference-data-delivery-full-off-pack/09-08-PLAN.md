<objective>
Prove, on real hardware, the two behaviors 09-VALIDATION.md's Manual-Only Verifications table marks as impossible to exercise inside `flutter test`: resumable/pausable/background-continuing downloads (native `URLSession`/`WorkManager` platform channels) and the live SQLite DETACH/re-ATTACH swap while `AppDatabase` already has an open, actively-queried connection.

Purpose: every automated test in Plans 09-01 through 09-06 mocks `background_downloader` and constructs its own isolated `AppDatabase` fixture -- neither proves the real platform-channel behavior or the real live-swap timing this feature's core value proposition depends on. 09-RESEARCH.md's Environment Availability table is explicit that a real CDN "genuinely blocks true end-to-end verification... not blocking planning or most implementation, only the final real-network verification step" and recommends testing against a throwaway local server first. Building that local server is squarely within this plan's own capability (`dart:io HttpServer`, no external dependency) -- only the "against the real eventual CDN" half is deferred, mirroring how Phase 7's real-device auth checks were logged as a documented STATE.md Pre-Launch Blocker rather than silently skipped. Plan 09-07 (the build-side script producing the smoketest fixture this plan's checkpoints point at) runs in Wave 1 with no file overlap or technical dependency on Plans 09-02 through 09-06 -- it is declared as a dependency here purely so this plan's Wave-7 checkpoints can rely on 09-07 having already landed, and this plan additionally regenerates the fixture itself at the start of Task 1 rather than assuming a `/tmp` artifact from an earlier session survived untouched (`/tmp` is not guaranteed to persist across reboots/session boundaries).

Output: a local Range-capable test server (automated, reusable for any future regression), a freshly-regenerated smoketest fixture at a known, correctly-named path, and two completed real-device checkpoints whose outcomes get logged for the pre-launch record (mirrors Phase 3's 03-05-PLAN.md and Phase 7's STATE.md Pre-Launch Blockers entry).
</objective>
