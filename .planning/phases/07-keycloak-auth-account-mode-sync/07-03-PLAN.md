<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| App <-> system browser (Keycloak) | Authorization Code + PKCE handoff; the app never sees a raw password |
| App <-> Keycloak `/userinfo` and `/.well-known/openid-configuration` | First-party HTTPS calls carrying a bearer token (userinfo) or nothing (discovery) |
| App <-> assumed `DELETE {backend}/me/account` | Bearer-token-authenticated call against a contract Tomris has not built yet (07-RESEARCH.md Assumption A2) |
| App <-> `flutter_secure_storage` (OS Keychain/Keystore) | Refresh token + cached email at rest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Information Disclosure | Refresh token at rest | mitigate | `flutter_secure_storage` only (Keychain/hardware-backed cipher), never `SharedPreferences`; access token kept in-memory only, never persisted |
| T-07-03-02 | Tampering | Authorization code interception | mitigate | PKCE code_verifier/challenge binding, entirely internal to `flutter_appauth`'s native AppAuth SDK -- no app-side crypto |
| T-07-03-03 | Repudiation / Tampering | Stale cached "logged in" UI after genuine server-side revocation | mitigate | `_isGenuineInvalidation` distinguishes OAuth-error-coded rejections from connectivity failures and forces `AuthUnauthenticated(sessionExpired: true)` only on the former |
| T-07-03-04 | Tampering | `DELETE /me/account` built against an unconfirmed backend contract | accept | Isolated to a single method (`deleteAccount()`) per 07-RESEARCH.md Pitfall 5 -- a future contract change is a one-method fix, not a structural rework; failure path leaves no local state change |
| T-07-03-05 | Information Disclosure | Access token leaking via logs | accept | Access token never persisted or logged; project already has zero crash-reporting/analytics SDKs (PRIV-07) eliminating the most common leak vector |
</threat_model>
